單元 02

搜尋演算法

建立日期：2026-11-16　預估閱讀：約 12 分鐘

學習目標

  • 說明 BFS 用佇列（queue）、DFS 用堆疊（stack）的原因
  • 分辨爬山法（區域視野）與最佳優先搜尋（全域視野）
  • 理解分支界限法如何用「下界」砍掉不可能的分支，並看懂旅行推銷員問題的成本矩陣縮減
  • 會用 f(n) = g(n) + h(n) 手算 A* 搜尋，並說明 h(n) ≤ h*(n) 為何重要

一、為什麼需要搜尋

許多問題（拼圖、路徑規劃、排程）可以畫成一棵「狀態樹」：根是起點，每個節點是一種狀態，往下展開就是走一步後的各種結果。搜尋策略決定的是下一個要展開哪個節點。

策略怎麼選下一個節點資料結構／依據
廣度優先（BFS）一層一層展開佇列 queue
深度優先（DFS）先一路走到底，不行再回頭堆疊 stack
爬山法在目前節點的子節點中選區域最佳者評估函數 f(n)
最佳優先在所有待展開節點中選估計成本最佳者排序後的清單
分支界限法用下界剪掉不可能比目前最佳解更好的分支下界 lower bound
A*最佳優先＋f(n) = g(n) + h(n)保證 h(n) ≤ h*(n)

二、盲目搜尋：BFS 與 DFS

廣度優先搜尋（Breadth-First Search）

以 8 數字拼圖（8-puzzle）為例：先把起始盤面的所有下一步展開，再展開這些盤面的下一步，逐層擴張。展開過的節點放進佇列，先進先出，所以淺層節點一定先處理。

比喻：像在水池丟一顆石頭，漣漪一圈一圈往外擴；離起點越近的位置越早被碰到。

深度優先搜尋（Depth-First Search）

用堆疊引導，後進先出，所以會沿著一條路一直往下探。投影片的例子是「子集合和問題」：

  • S = {7, 5, 1, 2, 10}，是否存在子集合 S′ ⊆ S，使 S′ 的總和為 9？
  • 依序決定要不要選 7、5、1…：選 7 後再選 5 得 12，已超過 9，捨棄；改選 1 得 8，再往下選 2 得 10、選 10 得 18，都超過，捨棄；回頭改選 2 得 7 + 2 = 9，找到目標。

比喻：走迷宮時一路走到死路，再退回最近的岔路換方向。

三、啟發式搜尋：爬山法與最佳優先

爬山法（Hill Climbing）

  • 是深度優先搜尋的變形，每次選區域最佳的節點展開。
  • 8 數字拼圖的評估函數：f(n) = d(n) + w(n)，其中 d(n) 是節點 n 的深度，w(n) 是錯位的方塊數。f 越小越好。
  • 投影片的範例中，起始盤面 f = 3，其子節點 f 為 4、4、5、5，選 4 的繼續往下，最後走到目標。

最佳優先搜尋（Best-First Search）

結合深度優先與廣度優先，從「所有」已產生的節點中挑估計成本最好的，具有全域視野。做法：

  • Step 1：建立只含根節點的清單。
  • Step 2：取出清單第一個元素並展開；若其子節點之一是目標就停止，否則把子節點加入清單。
  • Step 3：依估計函數值把整份清單排序。
  • Step 4：清單為空則失敗，否則回到 Step 2。

差別一句話：爬山法只看「現在站的地方」的鄰居；最佳優先會回頭看「所有還沒走的選項」。所以爬山法可能卡在區域最佳，最佳優先較不會。

四、分支界限法（Branch-and-Bound）

用來有效率地解最佳化問題。核心想法：每個分支都算出成本的「下界」，只要下界已經比手上最好的完整解還差，就整支剪掉。

例一：多階圖最短路徑

圖有 V0 → 三個 V1 節點 → 三個 V2 節點 → V3 共四層。分支界限法逐層展開並累計成本，成本超過目前最佳解的分支就剪掉。我自行驗算，最短路徑成本為 5，例如 V0 → V1,1 → V2,3 → V3（1 + 3 + 1）；V0 → V1,3 → V2,2 → V3（2 + 2 + 1）也是 5。

例二：旅行推銷員問題（TSP，NP-complete）

給定 7 個城市的成本矩陣（第 i 列、第 j 行為 i → j 的成本，對角線為 ∞），求走完所有城市回到起點的最小成本。

  • 縮減成本矩陣：每列、每行各減去一個常數，使每列每行至少有一個 0。減掉的總和就是解的下界。
  • 先減各列：3、4、16、7、25、3、26，共 84。
  • 再減第 3、4、7 行：7、1、4，共 12。
  • 下界 = 84 + 12 = 96：任何完整路線成本都至少是 96。

分支：選一條弧（4→6）

分支下界說明
包含弧 4-699刪掉第 4 列、第 6 行，並把 (6,4) 設為 ∞（否則會形成小環路）。投影片第 15 頁寫 96，最後的決策樹寫 99；縮減後的第 5 列最小值是 3，所以應為 96 + 3 = 99
不含弧 4-6128路線必須改走從 4 出發的其他弧，最便宜的是 4-1（成本 32），所以 96 + 32 = 128

持續分支（含／不含 3-5、2-1、1-4、6-7、5-2、7-3）後，得到完整路線 1-4-6-7-3-5-2-1，成本 126。其他下界已經 ≥ 126 的分支（128、153、141）直接剪掉。

比喻：找最便宜的環島路線時，如果某段已經讓預算超過 126，後面不管怎麼走都不可能更便宜，就不必再往下算。投影片中下界 117、125 的分支標為待展開，但並未畫出後續。

五、A* 演算法

  • 用來解最佳化問題，採最佳優先策略。
  • 節點 n 的成本函數：f(n) = g(n) + h(n)
  • g(n)：從根到 n 已花的成本；h(n)：從 n 到目標的估計成本；h*(n)：從 n 到目標的真實成本。
  • 只要保證 h(n) ≤ h*(n)（估計不會高估），就有 f(n) ≤ f*(n)。
  • 停止條件：當被選中的節點同時是目標節點時才停止，此時得到的解就是最佳解。

比喻：導航軟體估計「剩下的路」時，寧可樂觀（估少一點）也不要悲觀；因為估太高，可能把真正最短的路線誤判成很遠而被冷落。

範例逐步走一遍

圖的節點為 S、A、B、C、D、V5、T，邊成本：S→A 2、S→B 4、S→C 3；A→C 3、A→D 2；C→D 2、C→V5 2；B→V5 2；D→V5 1、D→T 3；V5→T 5。投影片的 h(n) 取「該節點所有出邊成本的最小值」，目標節點 h = 0。

步驟展開新節點的 g、h、f
1根節點 RA：2+2=4；B：4+2=6；C：3+2=5
2A（f 最小）D：4+1=5；E：5+2=7
3C（與 D 同為 5）F：5+1=6；G：5+5=10
4DH：5+5=10；I（目標）：7+0=7
5B（f = 6）J：6+5=11
6F（f = 6）K：6+5=11；L（目標）：8+0=8

此時清單中 f 最小的是目標節點 I（f = 7），其他節點 f 都 ≥ 7，所以停止。最佳解成本為 7，對應路徑 S → A → D → T（2 + 2 + 3）。注意 L 雖然也是目標，但成本是 8，不是最佳；這也是為什麼要「選中才停」，而不是「一產生目標就停」。
